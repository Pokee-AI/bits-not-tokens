# Results

Fifteen runs: 5 corpora × seeds {1, 2, 3}, all complete, no crashes, no reruns. Every
number below is regenerated by `python analysis/make_figures.py` from `results/runs/*.csv`
and `artifacts/*/nk_*.npz` (`results/summary.json` holds the machine-readable version).
Frozen LR = 3e-4 (`results/lr_sweep.csv`: 0.259 bits at 3e-4 vs 0.301 at 1e-3 after 1M
documents on Z05_n0 seed 1). Model: 31,524,864 non-embedding parameters (34.35M total).

**Headline: H1 FAIL, H2 FAIL against the pre-registered criteria.** The learner is far
from ideal in this world — it needs on the order of ten exposures of a fact to store it —
and that learner-side threshold, not the data's bit count, dominates both hypotheses.
The four Zipf corpora *do* collapse well on the bits-delivered axis (Figure 1), but the
EQ4 corpus, which delivers 17× more bits than any other, stores essentially nothing.

Fit window: measurement points with 0.05 ≤ loss ≤ 6 bits (`results/beta_fits.csv`).

|---|---|---|---|---|---|---|---|---|---|
| Z05_n0  | 0.5 | 0  | 0.246 | 0.244 | 0.246 | **0.245** | 0.333 | 0.361 | 12 (30K–10M docs) |
| Z05_n64 | 0.5 | 64 | 0.275 | 0.279 | 0.275 | **0.276** | 0.333 | 0.361 | 12 (30K–10M docs) |
| Z10_n0  | 1.0 | 0  | 0.488 | 0.495 | 0.480 | **0.488** | 0.500 | 0.500 | 5 (30K–248K docs) |
| Z10_n64 | 1.0 | 64 | 0.570 | 0.527 | 0.592 | **0.563** | 0.500 | 0.500 | 6 (30K–421K docs) |

Notes. For a = 1.0 the model's loss drops below 0.05 bits after ~250K–420K documents, so
the fit uses only the first 5–6 points; for a = 0.5 all 12 points are in the window. The
ideal learner over the same document range gives 0.361 for a = 0.5 (the asymptotic

The model's loss is 2–5× above the ideal learner everywhere (`figures/supp_loss_vs_docs`)
and its slope for a = 0.5 is shallower than both the prediction and the ideal learner.

## 2. Change in β between n = 0 and n = 64

- a = 0.5: β(n64) − β(n0) = **+0.031** (0.276 − 0.245); per-seed range of the difference 0.029–0.036.
- a = 1.0: β(n64) − β(n0) = **+0.075** (0.563 − 0.488); per-seed range 0.032–0.112.

Both exceed the 0.03 criterion (a = 0.5 marginally, a = 1.0 clearly). Filler makes the
curve steeper: the n = 64 model starts worse (higher loss at 30K docs) and catches up.

## 3. Horizontal shift in tokens between n = 0 and n = 64 at matched bits stored

Seed-averaged curves, log-log interpolation (`results/token_shift.csv`):

| a | facts stored T | tokens, n = 0 | tokens, n = 64 | ratio n64 / n0 |
|---|---|---|---|---|
| 0.5 | 1000 | 5.75M | 48.4M | **8.4×** |
| 0.5 | 2000 | 18.4M | 174M | **9.5×** |
| 0.5 | 3000 | 56.4M | 426M | **7.5×** |
| 1.0 | 1000–3000 | never reached (max ≈ 430 facts stored at 10M docs) | – | – |

The pure token-count ratio between the two corpora is 76/12 ≈ 6.3 (mean non-PAD tokens
per document). The observed shift is larger (7.5–9.5×), so filler costs slightly more
than its token count: at matched documents the n = 64 model stores ~7 % fewer bits.
For a = 1.0, at matched tokens (1e7) the n = 0 model has stored 2,760 bits vs 972 for n = 64.

## 4. H2 spreads (x at which the seed-averaged curve first reaches T facts stored)

`results/h2_crossings.csv`, `results/h2_spreads.csv`. Spread = max / min over corpora that reach T.

| T | corpora reaching T | spread in training tokens | spread in bits delivered |
|---|---|---|---|
| 1000 | Z05_n0, Z05_n64 (Z10_n0, Z10_n64, EQ4_n16 excluded: never reach T) | **8.4** | **1.20** |
| 2000 | Z05_n0, Z05_n64 (same three excluded) | **9.5** | **1.30** |
| 3000 | Z05_n0, Z05_n64 (same three excluded) | **7.5** | **1.12** |

Criterion at T = 3000: tokens ≥ 10 and bits ≤ 2. Bits passes (1.12); tokens fails (7.5).
Only the two a = 0.5 corpora ever store 1000 facts: the a = 1.0 corpora deliver only
~4,400 facts in 10M documents and store ~430 of them; EQ4 stores ~0 (see §5). With just
those two corpora the token spread can only reflect the filler ratio.

Supplementary matched-x comparison over the four Zipf corpora (all seeds averaged):
at 3×10⁴ bits delivered the stored bits are {Z05_n0 3529, Z05_n64 2285, Z10_n0 4285,
Z10_n64 3741}, spread **1.9**; at 5×10⁴ bits delivered, spread **1.35**. At 10⁷ training
tokens the same four corpora span {17483, 3733, 2760, 972} bits stored, spread **18**;
at 5×10⁷ tokens, spread **16**. So the collapse H2 describes is real for the Zipf
corpora, but the pre-registered test cannot see it because three corpora never reach T.

## 5. Position relative to the identity line (bits stored / bits delivered, last point)

| corpus | seed 1 | seed 2 | seed 3 | bits delivered at last point |
|---|---|---|---|---|
| Z05_n0  | 0.060 | 0.062 | 0.062 | 696K |
| Z05_n64 | 0.057 | 0.056 | 0.056 | 696K |
| Z10_n0  | 0.099 | 0.096 | 0.097 | 52K |
| Z10_n64 | 0.084 | 0.085 | 0.087 | 52K |
| EQ4_n16 | 1.9e-6 | 1.2e-5 | 2.6e-5 | 12,000K |

Every corpus sits 1–2 orders of magnitude below the identity line; EQ4 sits 5 orders
below it. EQ4's in-distribution object loss is 12.02–12.17 bits at *every* measurement
point (uniform over the 4,096 objects is 12.00) and its training loss of 5.08–5.12
nats/token is exactly the closed-form value for a model that knows the document format
and nothing about the facts (≈137 nats of template/subject/relation/object/filler
entropy over 27 predicted tokens). Four exposures per fact, spaced ~8K optimizer steps
apart, are below this learner's memorisation threshold at LR 3e-4. The pipeline itself
stores facts fine when exposures are plentiful (Zipf runs; test 5 reaches 100 % top-1 at
60 exposures per fact), and the unseen-fact control is at chance, so this is a result
about the learner, not a bug we could find.

## 6. Exposure-corrected axis I_eff = 12 Σ_k (1 − exp(−n_k / n0))

- Pre-registered fit (single n0, all corpora and seeds, 177 points, none dropped):
  **n0 = 0.030**, i.e. the fit runs to the lower bound where I_eff ≡ bits delivered.
  Reason: EQ4's ~0 stored bits cannot be collapsed by any n0, and its residuals dominate.
  Spread on this axis at T = 1000 / 2000 / 3000: 1.20 / 1.30 / 1.12 (two corpora, as in §4).
- Diagnostic fit excluding EQ4 (not pre-registered): **n0 = 9.9 exposures**; spreads
  1.21 / 1.30 / 1.12. An n0 of ~10 is consistent with the delivered→stored ratios above
  (the a = 1.0 corpora, whose delivered facts are seen more often, store a larger fraction).

## 7. Verdicts against PASS_CRITERIA.md

- **H1: FAIL.** Seed-averaged β for a = 0.5 is 0.245 (n = 0) and 0.276 (n = 64) against
  the predicted 0.333 — off by 0.088 and 0.057 (criterion ≤ 0.05). For a = 1.0, β is
  0.488 (n = 0, within criterion) and 0.563 (n = 64, off by 0.063). The n = 0 vs 64
  difference is 0.031 (a = 0.5) and 0.075 (a = 1.0), both ≥ 0.03.
- **H2: FAIL.** At T = 3000 the spread in bits is 1.12 (≤ 2, passes) but the spread in
  tokens is 7.5 (< 10, fails), computed over the only two corpora that reach T
  (Z05_n0, Z05_n64); Z10_n0, Z10_n64 and EQ4_n16 never reach 1000 facts stored.
- Unseen-fact control: at chance everywhere. Per-corpus mean top-1 on unseen facts
  2.2e-4 – 3.2e-4 vs chance 2.44e-4; max over all Zipf points 5.0e-4. The one larger
  value (EQ4, 3.4e-3 at 3.48M docs) is 1 hit in a control set of only 294 remaining
  unseen facts; at 4M docs the control set is empty (NaN, see DEVIATIONS.md #4).

# v2: held-out test of the x-axis claim (PASS_CRITERIA_v2.md)

Pre-registered after v1 (commit `4e73f29`), before any v2 run. Six held-out runs
(EQ16_n0, EQ16_n64, EQ32_n0 × seeds 1, 2; full K = 1,000,000; same model, LR 3e-4, protocol)
plus reruns of the fifteen v1 runs with per-fact hit saving for the absorption curve.
All 21 runs completed without errors. Wall time: EQ16 24–33 min, EQ32 49–50 min.

**Verdict: H2v2 FAIL.** None of the three held-out corpora reaches T = 300 stored facts
(or T = 200); EQ16_n64 alone reaches T = 100, at I_eff = 9.4 × 10⁶ — three orders of
magnitude outside the Zipf band [3.2 × 10³, 1.8 × 10⁴]. This outcome was predicted and
recorded before the runs (DEVIATIONS.md #11): I_eff with the frozen concave form credits
a single exposure with 9.6 % of a fact, while the absorption curve below shows the true
credit at 1–16 exposures is ≈ 0.

Per-seed values agree to ±0.01 in every bin (`results/absorption.csv`).

What it shows:

1. **Storage is a sigmoid in exposures, not the concave 1 − e^(−n/n0).** In the Zipf
   corpora a fact needs ~40–60 exposures to be stored with 50 % probability and ~130 to be
   stored reliably; below 8 exposures fewer than 1 in 12 is stored. This is why I_eff with
   any n0 fails on EQ corpora (DEVIATIONS.md #11).
2. **Filler barely changes absorption per exposure.** Z05_n0 and Z05_n64 are within 0.05 in
   every bin. Filler costs tokens (6–9× on the token axis, v1 §3), not exposures. The a = 1.0
   pair differs more (Z10_n64 below Z10_n0 at 17–64 exposures).
3. **Exposure count alone does not determine storage.** A fact seen 16 times in a Zipf corpus
   is stored 16–17 % (a = 0.5) or 3 % (a = 1.0) of the time; every fact seen 16 times in EQ16
   is stored 0.0 % of the time, and 32 times in EQ32 also 0.0 %. Same model, same LR, same
   world, same number of exposures. The rest of the corpus matters: Zipf corpora contain
   facts seen thousands of times, EQ corpora contain none.
4. **Exposure rate matters too (weaker evidence).** The same Z05_n0 run evaluated at an
   intermediate point gave 0.31 for the 9–16 bin vs 0.17 at the end — the facts occupying
   that bin earlier had a higher exposure rate.

## What v2 settles and what it leaves open

Settled: "bits delivered" is not the collapsing axis (v1), and neither is the
exposure-corrected I_eff with the concave form and a single n0 (v2). Storage per exposure
follows a sigmoid centred near 50 exposures in the Zipf corpora, and is zero at 4, 16 and
32 exposures in corpora where every fact has the same count. Filler does not change the
per-exposure absorption; repetition structure does.

Open: why identical exposure counts store 0 % in EQ and 3–17 % in Zipf. Two candidates the
present data cannot separate: (a) the frequent facts in a Zipf corpus bootstrap a retrieval
mechanism that rarer facts then reuse, and EQ corpora never build it (consistent with the
EQ in-distribution loss sitting at exactly 12.00 bits — no partial learning at all); (b)
interference from ~1M concurrently unstored facts overwrites each fact's update before it
recurs (~7,800 steps apart in EQ16), while in Zipf the stored popular facts contribute no
gradient and the effective competing set is far smaller. A mixed corpus (a small Zipf head
plus an EQ tail) would separate them. Also open: whether the sigmoid's centre moves with LR,
batch size or model size — only one learner configuration was run.

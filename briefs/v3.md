# Experiment Brief v3: Testing the Premise

This brief extends the existing `bits-not-tokens/` repo. Reuse the world (world seed 0, K = 1,000,000 facts, 12 bits each), the vocabulary, the document format, the one-document-per-row rule, the trainer, the evaluators and the measurement/cooldown procedure exactly as they stand, including any deviations already recorded in `DEVIATIONS.md`. Read this whole file before writing code.

## 0. Why this brief exists

v1 and v2 tested whether some count of "bits delivered" collapses learning curves. They failed, and the failures taught us the rules of this learner:

- A fact needs many exposures (roughly 50 for a 50% chance) before it is stored.
- A model on a flat, uniform corpus of 1M facts never leaves the initial plateau (object loss stays at 12.00 bits), so nothing is stored at all. Head-heavy data forms the recall mechanism; see Zucchet et al. (2025), arXiv 2503.21676.

Those are facts about the learner. v3 tests the actual premise:

> **Premise.** A web-like corpus wastes most of its tokens from the learner's point of view, so a small model trained on it ends far below its capacity. The same small model, on the same number of training tokens spent well, stores several times more, enough to match a much larger model trained on the raw corpus.

Three sources of waste: (1) exposures beyond what a fact needs, (2) facts seen too few times to ever be stored, (3) noise tokens.

## 3. Phase 0: token-waste accounting (no training)

From the existing Zipf runs (Z05_n0, Z05_n64, Z10_n0, Z10_n64; all seeds), using the saved final `n_k` arrays and the final checkpoints:

1. Evaluate every fact with n_k >= 1 and mark it stored or not (top-1 correct).
2. **Absorption curve:** P(stored) versus n_k in log-spaced bins. From it read c50 and c90, the exposure counts at which P(stored) first reaches 0.5 and 0.9 (linear interpolation in log n_k; report "not reached" if so).
3. **Waste decomposition**, as fractions of all training documents:
   - `unabsorbed` = documents spent on facts that ended up not stored
   - `excess` = sum over stored facts of max(0, n_k - c90)
   - `useful` = the remainder
   Also report the fraction of training *tokens* that were template + filler.
4. Report the share of documents taken by the single most popular fact and by the top 100 facts.

Write `results/v3_waste.csv` and a table in `RESULTS_V3.md`. This phase is descriptive; no pass/fail.

## 4. Phase A: dense-uniform calibration

Purpose: measure, per model size, how many exposures a fact needs when the data is uniform and dense enough to leave the plateau, and how long the plateau lasts.

### 4.1 Corpora

Uniform sampling (with replacement) over a fact subset of size K_sub, filler n = 0, 10,000,000 documents. The subset is the first K_sub facts in the popularity permutation.

| Model | K_sub values |
|---|---|
| S | 10,000 and 30,000 |
| M | 10,000 and 30,000 |
| L | 10,000, 30,000 and 100,000 |

Seeds 1 and 2. 14 runs.

### 4.2 Measurements

- Log in-distribution object loss every 1,000 optimizer steps. **Plateau length** = first step at which it drops below 11.5 bits (report in steps and documents; "never" if so).
- At each measurement point: fraction of the K_sub facts stored, and mean exposures per fact (= documents / K_sub).
- Per run: c50 and c90 on the fraction-stored versus mean-exposures curve, counting exposures from the start of training, and again counting only exposures after the plateau ended.
- Bits stored per parameter at the end of each run.

### 4.3 The constant c* (write to C_STAR.md, then commit)

For each model size, c* = c90 (exposures counted from the start of training) from the K_sub = 30,000 runs, seed mean, rounded up to the next multiple of 10, and capped at 400. If 90% is not reached with K_sub = 30,000, use the K_sub = 10,000 runs. If it is not reached there either, set c* = 400 and say so.

Also record W = 2 x the longest plateau length in documents observed for that model size across its Phase A runs and the v1 Z05_n0 runs (L only), rounded up to the next 50,000. W is the warm-up length used in Phase P.

**Stop condition:** if no Phase A run for a model size ever leaves the plateau, stop and report. Phase P is not meaningful for that size.

## 5. Phase P: the premise test

Fixed model, fixed budget of **training tokens**, three ways of spending it.

### 5.1 Base distribution

Shifted Zipf over all K = 1,000,000 facts: p_k proportional to (k + q)^-(1+a) with a = 0.5 and q = 1000, k = popularity rank. The shift keeps any single fact from dominating (the top fact is about 0.05% of draws). Add a unit test: empirical facts-delivered after 200,000 draws is within 1% of sum_k [1 - (1 - p_k)^N].

### 5.2 Corpora (budget B = 300,000,000 non-PAD training tokens each)

| Name | Sampling | Filler n | Meaning |
|---|---|---|---|
| RAW | shifted Zipf, no cap | 16 | web-like: redundant head, thin tail, noise |
| DEDUP | shifted Zipf; after warm-up, a fact that has reached c* exposures is never drawn again | 16 | repetition capped at what the learner can use |
| CURATED | same capped sampling as DEDUP | 0 | capped repetition and noise removed |

Rules for the capped stream:

- The first W documents are drawn uncapped from the shifted Zipf (warm-up, so the recall mechanism forms). They count toward n_k and toward the token budget.
- After warm-up, rebuild the sampling CDF over facts with n_k < c* every 50,000 documents, and reject any draw within a block that would exceed the cap.
- The stream ends when the token budget B is reached. Because capped facts drop out, the stream reaches deeper into the tail; that is the intended reallocation. If every fact reaches c* before B is spent, stop early and record the tokens used.
- c* and W are the per-model-size values from `C_STAR.md`. The curated data is therefore tuned to the learner, on purpose.

### 5.3 Run matrix

3 corpora x 3 model sizes (S, M, L) x seeds {1, 2} = 18 runs. Measurement points: 8 log-spaced token counts ending at B. The final point is the one used for pass/fail.

### 5.4 Measurements per point

`facts_delivered`, `facts_with_at_least_cstar_exposures`, `facts_stored` (top-1 over facts with n_k >= 1, minus chance), `bits_stored`, `bits_stored_per_param`, unseen-fact control accuracy (must stay near 1/4096), in-distribution object loss, train tokens, docs, wall time, seed, config hash, git commit. Write to `results/v3_premise.csv`.

Before launching, compute from the closed form and print for each corpus and model size the predicted number of facts that will reach c* exposures within budget B. Save as `results/v3_predicted_storable.csv`. This is a prediction made before the runs, to be compared afterwards.

## 6. Pass criteria (copy verbatim into PASS_CRITERIA_v3.md and commit before Phase A)

All comparisons use the final measurement point and the mean over seeds; per-seed values are also reported.

- **P1 (equal tokens).** For every model size, CURATED stores at least 3x as many facts as RAW. PASS only if it holds for S, M and L.
- **P2 (size equivalence).** The S model (about 2M parameters) trained on CURATED stores at least as many facts as the L model (about 31M parameters) trained on RAW.
- **Descriptive, no pass/fail.**
  - Attribution: DEDUP / RAW and CURATED / DEDUP ratios of facts stored, per model size, separating the effect of capping repetition from the effect of removing noise.
  - Headroom: bits stored per parameter for every (corpus, size), next to the reference values 2.0 (Allen-Zhu and Li, 2024) and 3.6 (Morris et al., 2025) bits per parameter.
  - Predicted versus actual: facts stored against `facts_with_at_least_cstar_exposures`.
- With two seeds there are no confidence intervals. Report per-seed values and the range.
- If a run never leaves the plateau, it counts as storing zero facts and the criterion is evaluated as such; do not rerun with changed settings to rescue it. Note it prominently.

## Amendments adopted on the implementer's review (before Phase A)

- **Checkpoints.** Phase 0 reads the existing `results/absorption.csv`; no weights needed. The optional §8 diagnostic would use a `--save-final` rerun of Z05_n0 seed 1, but only if that diagnostic is actually run.
- **c\* transferred from uniform to Zipf-shaped data** is stated as an explicit assumption, checked with a new measure, *cap adequacy*: among facts that reached c\* exposures, the fraction stored. Below 0.7 the run is flagged cap-limited, so an under-storing capped corpus is attributed to the cap and not to the premise.
- **W** is taken from the K_sub = 30,000 runs only (the runs that define c\*), capped at 1,000,000 documents, identical for both capped corpora; if the cap binds, `C_STAR.md` says so.
- **LR tie-break.** If all three rates store nothing at 1M documents, extend to 3M; if still nothing, pick the lowest loss and expect the Phase A stop condition to fire.
- **Parameters.** Non-embedding is primary; total is reported alongside.
- **Measurement points** start at B/300; one batch of slack is accepted and noted once in `DEVIATIONS.md`.
- **Trivial pass.** P1 counts a model size only if RAW stores at least 100 facts there, requires the 31M model to be evaluable, and never counts a non-evaluable size as a pass. P2 has the same guard.
- **The 3× bar** is kept; the measured ratio is compared against the one implied by the predicted-storable table, so a 3× result when 10× was predicted is visible as a shortfall.
- **S saturating under CURATED** is an expected outcome to report, with the bits per parameter at which it flattens.
- **Naming.** DEDUP is CAPPED throughout, with a note that it caps repetitions per fact and does not deduplicate documents.

The criteria as amended are the text of `PASS_CRITERIA_v3.md`.

# Experiment Brief v4.1: The Premise Test, Made Stationary

**Changes from v4 (decisions on the implementer's review):** level selection is restricted to levels that pass the head-loss guard on seed 1; CURATED-c shares tau with FLAT-c so attribution is clean, with one extra CURATED-only tight level; predictions average the absorption curve over the Poisson exposure distribution and state the count-only assumption; the determinism check uses a `--stop-after-points` flag; measurement notes clarified.

This brief extends the existing `bits-not-tokens/` repo. Reuse the world, vocabulary, document format, one-document-per-row rule, models S / M / L with their frozen learning rates, trainer, evaluators and measurement procedure exactly as they stand in v3, including recorded deviations. Read this whole file before writing code.

## 0. What went wrong in v3, and what v4 changes

v3's capped stream removed a fact forever once it reached c* exposures. Popular facts hit the cap early and vanished, so the training distribution slid through the fact list over time. That is continual learning under distribution shift, and the result was total forgetting of every capped fact. A real curated corpus is shuffled: a fact's occurrences are spread over the whole run. v3 tested the wrong thing. That was an error in the brief, not in the implementation.

v3 also transferred c* from dense uniform data to a differently spaced stream, and cap adequacy (0.003 to 0.15) showed the transfer failed.

v4 fixes both:

1. **Stationary sampling.** Curated corpora are i.i.d. draws from a *flattened* version of the raw distribution. No fact ever disappears; popular facts are simply drawn less often, all the way through training.
2. **A dose-response curve instead of one transferred constant.** Four pre-specified flattening levels per corpus type, so the experiment measures how much flattening helps and where it starts to hurt, without assuming c* in advance.
3. **Selection on one seed, confirmation on the other,** so picking the best level cannot inflate the result.

**Stopping rule.** This is the last redesign of the premise test in the random-fact world. Whatever it shows is what gets reported.

## 2. Distributions

Raw distribution p (unchanged from v3): shifted Zipf over all K = 1,000,000 facts, p_k proportional to (k + 1000)^-1.5.

Flattened distribution at threshold tau:

```
q_k(tau) = min(p_k, tau) / Z(tau),     Z(tau) = sum_k min(p_k, tau)
```

Every fact keeps a nonzero probability for the entire run. Facts more popular than tau are all drawn at the same capped rate; the freed probability mass flows to the tail in proportion to p.

**Flattening level c** is defined on the FLAT corpus: tau_c solves `N_stat_FLAT * tau / Z(tau) = c`, where `N_stat_FLAT` is FLAT's number of stationary-phase documents for that model size (section 3). Solve by bisection. Levels: **c in {1000, 300, 100, 30}**.

**CURATED-c uses the same tau_c as FLAT-c.** CURATED is then the same distribution with about 2.3x the documents, which is exactly what removing noise buys, and its capped facts receive about 2.3c exposures. This keeps CURATED / FLAT a clean measure of noise removal. One extra CURATED-only level, **CURATED-x30**, uses the tau at which CURATED's own capped facts receive 30 exposures, so the CURATED sweep also reaches a tight cap. It has no FLAT counterpart, is excluded from attribution, and is eligible for level selection like any other CURATED level. Add a unit test that the solved tau reproduces c to within 0.5%, and that empirical exposure counts of capped facts over a full simulated stream have mean within 2% of c (plus warm-up exposures).

## 3. Corpora

Budget B = 300,000,000 non-PAD training tokens per run, as in v3.

| Name | Sampling | Filler n |
|---|---|---|
| RAW | i.i.d. from p | 16 |
| FLAT-c | warm-up, then i.i.d. from q(tau_c) | 16 |
| CURATED-c | warm-up, then i.i.d. from q(tau_c) | 0 |

- **Warm-up:** the first W documents are i.i.d. from p, with W per model size taken from the committed `C_STAR.md`. Purpose: form the recall mechanism, which flat data alone does not do (v2, and Zucchet et al. 2025). After warm-up the distribution switches once to q and never changes again. No fact is ever removed.
- `N_stat` = (documents that fit in B at that corpus's mean document length) minus W. Because CURATED documents are shorter, CURATED runs see more documents than FLAT runs for the same B; tau does not change (section 2). Compute and log N, N_stat, tau, Z, the number of facts at the cap, and the expected exposures of a capped fact for every (corpus type, level, model size).
- **RAW is not rerun.** Reuse the v3 RAW results for S, M, L (seeds 1 and 2). First verify determinism by rerunning RAW-S seed 1 with the full budget B but a `--stop-after-points 2` trainer flag (the measurement points are defined by B, so a smaller budget would not reproduce the rows; log the flag in `DEVIATIONS.md`) and confirming identical CSV rows; if they differ, rerun all RAW runs under v4 code and say so.

Run matrix: 2 corpus types x 4 levels x 3 sizes x seeds {1, 2} = 48 runs, plus CURATED-x30 (3 sizes x 2 seeds) = 54. Priority order if time is short: FLAT, then CURATED, then CURATED-x30. FLAT-1000 caps only a few thousand facts and should land close to RAW; treat it as an anchor that checks the pipeline, not a wasted level. After a smoke test, report projected wall time for the full matrix before launching.

## 4. Measurements at each point (8 log-spaced token counts from B/300 to B)

All from v3, plus:

1. `facts_stored`: top-1 correct over facts with n_k >= 1, minus chance. Primary.
2. `weighted_acc_p`: top-1 accuracy with facts weighted by the RAW distribution p. This is top-1 accuracy on the existing 200,000-document in-distribution eval set, which is already sampled from p with the fixed eval seed; use that same set for every corpus. This is how well the model serves the raw usage distribution; it guards against buying tail facts by losing the head.
3. `head_loss_bits`: mean object loss over the 1,000 most popular facts. Values near or above 12 bits mean the head is lost.
4. Absorption curve at the final point: P(stored) versus n_k in log-spaced bins, per run.
5. Bits stored per non-embedding parameter (and per total parameter).
6. Unseen-fact control accuracy (must stay near 1/4096).

Write to `results/v4_premise.csv`; absorption curves to `results/v4_absorption.csv`.

## 5. Predictions, committed before launch

For each model size, take the empirical absorption curve A_size(n) = P(stored | n_k = n) from that size's v3 RAW runs at the final point (seed mean, log-binned, linearly interpolated in log n, clipped to [0, 1], and held flat beyond the largest observed bin). This curve was measured under stationary i.i.d. sampling at this run length, which is the right regime for v4.

For every v4 corpus and level, compute the expected exposure count lambda_k of every fact (warm-up plus stationary phase) and the predicted facts stored = sum_k E[A_size(n)] with n ~ Poisson(lambda_k), i.e. the absorption curve averaged over the exposure distribution, not evaluated at its mean. **Stated assumption:** A_size was measured under i.i.d. sampling for the whole run, so the prediction treats absorption as a function of exposure count alone. For head facts that receive most of their exposures during warm-up (for S, roughly 300 of about 330), that is precisely the assumption v3 suggests may fail. That is the question being asked, not a defect to fix. Save to `results/v4_predicted.csv` with the predicted ratio to RAW, and commit.

The scientific question this sets up: **is absorption a function of a fact's own exposure count alone, or does the rest of the corpus matter?** If actual tracks predicted, the absorption curve transfers and flattening works as simple accounting says. If actual falls short, the shortfall measures interference from trying to hold more facts at once.

## 6. Pass criteria (copy verbatim into PASS_CRITERIA_v4.md and commit before any v4 run)

**Level selection.** For each model size and corpus type, consider only the levels that pass the P3 head-loss guard on **seed 1** (against RAW seed 1). Among those, the selected level is the one with the most facts stored at B on seed 1. If no level passes P3 on seed 1, report NO ELIGIBLE LEVEL for that size and corpus type, and P1 for that size is FAIL. All pass/fail comparisons then use **seed 2 only**, at the selected level, against RAW seed 2. Seed 1 numbers are reported but decide nothing except the selection.

- **P1 (equal tokens), same bar as v3.** CURATED at the selected level stores at least 3x the facts RAW stores. A model size is evaluable only if RAW stores at least 100 facts. PASS requires L to be evaluable and the ratio to hold at every evaluable size.
- **P2 (size equivalence), same bar as v3.** S on CURATED (selected level, seed 2) stores at least as many facts as L on RAW (seed 2). Evaluable only if L on RAW stores at least 100 facts.
- **P3 (no head loss), required for P1 and P2 to count.** Checked again on seed 2: at the selected level, `weighted_acc_p` is no more than 0.02 (absolute) below RAW's at the same size and seed. If P3 fails for a size, that size's P1 result is reported as FAIL (HEAD LOSS).
- **Descriptive, no pass/fail.**
  - Dose-response: facts stored and `weighted_acc_p` versus level c, per size and corpus type, both seeds, with RAW as the reference.
  - Attribution: FLAT / RAW (flattening alone) and CURATED / FLAT (noise removal) at each level.
  - Predicted versus actual facts stored for every run (section 5), and the actual/predicted ratio.
  - M on CURATED versus L on RAW (a 4x size gap), alongside P2's 16x gap.
  - Bits per parameter against the 2.0 and 3.6 reference values.
  - Plateau: any run whose in-distribution loss never drops below 11.5 bits counts as storing zero facts and is not rerun.
- With one confirmation seed there are no confidence intervals. Say so, and report v3's observed seed-to-seed spread next to the verdicts for context.
